# 인스타 벤치마킹 피그마 플러그인 — 설계 문서

- 작성일: 2026-08-06
- 상태: 승인됨 (사용자 승인 완료, 구현 대기)

## 배경 / 문제

사용자는 콘텐츠 에디터로, 콘텐츠 기획 시 타 인스타그램 게시물의 레이아웃을 벤치마킹한다.
현재 워크플로우:
1. 인스타 게시물을 캡처하거나, 게시글 링크를 다운로더 사이트에 올려 이미지 파일로 받음
2. 받은 이미지를 피그마에 업로드
3. 폰트 사이즈 등을 자로 대보듯 일일이 비교하며 벤치마킹

이 흐름에서 반복적인 "다운로드 → 피그마 업로드" 과정과, 이미지 속 특정 오브젝트(예: 텍스트 박스, 로고, 인물)만 따로 떼어내 비교하고 싶을 때 겪는 불편함을 해소하고자 한다.

## 목표

하나의 피그마 플러그인에 두 기능을 담는다:

1. **링크 임포트**: 인스타그램 게시물 링크를 붙여넣으면 이미지(+캡션)가 자동으로 피그마 캔버스에 실제 픽셀 크기로 정렬되어 올라감
2. **매직레이어**: 캔버스에 있는 이미지를 클릭 한 번으로 오브젝트 단위로 분리해 독립된 레이어로 만듦 (캔바 Magic Grab과 유사)

돈이 들지 않고, 로컬에서 완전히 동작해야 한다 (SaaS/유료 API 의존 없음).

## 비목표 (Out of scope, v1)

- 배경에 생기는 구멍을 AI로 자동 메우는 인페인팅 (v1은 투명 처리만)
- 인스타 캡션을 실제 폰트/서체까지 복제하는 것 (텍스트 레이어로만 가져옴, 폰트는 시스템 기본)
- 인스타 외 타 플랫폼(유튜브, 틱톡 등) 지원
- 로그인이 필요한 비공개 계정 게시물 지원
- 매직레이어의 다중 오브젝트 일괄 자동 분리 (v1은 클릭 기반 1개씩)

## 아키텍처

```
[Figma 플러그인 UI (iframe, ui.html)]
   │  1) 인스타 링크 입력
   ▼
[로컬 Node 서버 (localhost:3457)]  ──fetch──▶  [Instagram 게시물 페이지]
   │  2) HTML 파싱: og:image, 캐러셀 이미지 URL들, 캡션, 작성자
   ▼ (JSON 응답)
[플러그인 UI] ──postMessage──▶ [code.ts (Figma 메인 스레드)]
                                    │ 3) 이미지 fetch(UI에서 바이트 확보 후 전달) →
                                    │    figma.createImage() → 프레임/이미지 노드/텍스트 노드 생성
                                    ▼
                              [Figma 캔버스]

[매직레이어 흐름]
캔버스에서 이미지 선택 → 플러그인 UI 안 편집 화면에 이미지 렌더
   │  SAM 세그멘테이션 (transformers.js, Xenova/slimsam-77-uniform, WASM/WebGPU)
   │  브라우저(iframe) 안에서 전부 처리, 외부 서버로 이미지 전송 없음
   ▼
마스크 확정 → 알파 채널 있는 PNG 생성 → code.ts에 전달
   → 원본 위치와 정확히 겹치는 새 이미지 노드 생성 (독립적으로 이동/리사이즈 가능)
   → 원본 이미지의 해당 영역은 투명 처리된 새 이미지로 교체
```

### 구성 요소

| 구성 요소 | 역할 |
|---|---|
| `manifest.json` | 플러그인 메타, `networkAccess.allowedDomains`에 `http://localhost:3457`, 모델 CDN(huggingface.co 등) 등록 |
| `code.ts` | Figma 메인 스레드. 선택된 노드 읽기, 이미지/텍스트 노드 생성, UI와 postMessage로 통신 |
| `ui.html` / `ui.ts` | 플러그인 패널 UI. 링크 입력 폼, 매직레이어 편집 캔버스(클릭으로 포인트 프롬프트), 로컬 서버 fetch, SAM 추론 |
| 로컬 Node 서버 (`server.js`) | 기존 `depth-openpose-extractor`와 동일 패턴. 인스타 링크 fetch 후 이미지 URL/캡션 파싱 API 제공 (`GET /parse?url=...`) |

### 기능 1 — 링크 임포트 상세

1. 사용자가 플러그인 패널에 게시물 링크 붙여넣기 → "가져오기" 클릭
2. UI가 로컬 서버 `/parse?url=...` 호출
3. 서버: 인스타 게시물 페이지 HTML을 fetch → `og:image`, 캐러셀이면 페이지 내 이미지 URL 목록, 캡션(`og:description` 등), 작성자 계정명 파싱 → JSON 응답
4. UI가 각 이미지 URL을 fetch해서 바이트로 확보 (CORS 허용 도메인이면 UI에서 직접, 막히면 로컬 서버가 프록시)
5. UI → code.ts로 이미지 바이트 배열 + 캡션 텍스트 전달
6. code.ts: 새 프레임 생성 (이름: `{계정명}_{날짜}`) → 이미지들을 원본 픽셀 크기로 가로 나열 배치 → 프레임 하단에 캡션 텍스트 노드 추가

### 기능 2 — 매직레이어 상세

1. 사용자가 캔버스에서 이미지 레이어 하나 선택 → 플러그인의 "매직레이어" 버튼 클릭
2. code.ts가 선택된 노드의 이미지 바이트를 `exportAsync`로 추출해 UI로 전달
3. UI 안에 편집 화면(canvas)이 열리고 이미지가 렌더됨
4. 이미지 1회 인코딩(SAM) → 사용자가 오브젝트 클릭(포인트 프롬프트) → 마스크 실시간 계산 및 오버레이 표시. Shift+클릭으로 마이너스 포인트 추가해 마스크 다듬기
5. "추출" 클릭:
   - 마스크 영역만 알파 채널 있는 PNG로 잘라냄 (신규 레이어용)
   - 원본 이미지에서 해당 마스크 영역을 투명 처리한 PNG 생성 (배경용, 구멍 남음)
6. UI → code.ts로 두 PNG 전달 → code.ts가 원본 노드의 이미지를 "배경용 PNG"로 교체하고, 그 위에 원본과 동일한 위치/크기의 새 이미지 노드를 "추출된 PNG"로 생성
7. 새로 생긴 레이어는 Figma 상에서 일반 노드이므로 자유롭게 이동/리사이즈 가능. 필요하면 같은 방식으로 다른 오브젝트도 반복 추출 가능

## 에러 처리

- 로컬 서버가 꺼져 있으면 → UI에서 "로컬 서버를 실행해주세요 (`node server.js`)" 안내와 재시도 버튼
- 인스타 페이지 파싱 실패 (구조 변경, 삭제된 게시물, 비공개 계정) → 명확한 실패 메시지, 다른 기능에는 영향 없음
- SAM 모델 다운로드 실패(오프라인 등) → 에러 메시지 + 재시도 버튼. 최초 1회 성공하면 이후 캐시로 오프라인 동작
- WebGPU 미지원 환경 → WASM 자동 폴백 (transformers.js 기본 동작), 속도 저하 안내
- 선택 없이 매직레이어 클릭 → "이미지를 먼저 선택해주세요" 안내
- 이미지가 아닌 노드 선택 시 → 매직레이어 비활성화 상태로 표시

## 검증 방식

자동 테스트 없이 수동 검증 (기존 자매 프로젝트 `depth-openpose-extractor`, `like-collage`와 동일 컨벤션):

- 로컬 서버 켠 상태로 실제 공개 인스타 게시물 링크(단일 이미지) 임포트 → 프레임/이미지/캡션 생성 확인
- 캐러셀 게시물 링크 임포트 → 이미지 여러 장 가로 배치 확인
- 임포트된 이미지에 매직레이어 실행 → 오브젝트 클릭 → 마스크 정확도 확인 → 추출 → 새 레이어 독립 이동 확인
- 로컬 서버 꺼진 상태에서 링크 임포트 시도 → 에러 안내 확인
- 삭제된/비공개 게시물 링크 시도 → 에러 안내 확인

## 리스크

- 인스타그램 HTML 구조는 예고 없이 바뀔 수 있어 파싱 로직이 깨질 수 있음 → 로컬 서버의 파싱 부분만 별도 모듈로 분리해 유지보수 용이하게 구성
- 스크래핑은 인스타그램 서비스 약관상 그레이존. 개인적 벤치마킹 목적의 로컬 도구이며 재배포/대량 수집이 아니므로 리스크는 낮다고 판단하되, 사용자가 인지하고 사용
